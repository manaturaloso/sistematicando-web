# 1. CONTEXTO COMPLETO DEL PRODUCTO

## 1.1. ¿Qué es Sistematicando?

Sistematicando es una plataforma SaaS de gestión empresarial, diseñada para centralizar y simplificar las operaciones de negocios de gastronomía, hospitalidad y entretenimiento.

Su filosofía es:

**Todo tu negocio, bajo control.**

El producto busca permitir que las empresas gestionen distintas áreas de su operación desde un ecosistema tecnológico conectado, en lugar de depender de múltiples plataformas independientes, hojas de cálculo, procesos manuales y herramientas desconectadas.

Sistematicando se concibe como una solución:

- Integral.
- Modular.
- Escalable.
- Fácil de entender.
- Fácil de utilizar.
- Moderna.
- Accesible comercialmente.
- Adaptable a diferentes tipos de negocio.
- Preparada para organizaciones con uno o varios establecimientos.

## 1.2. Sectores principales

### Restaurantes

Necesitan administrar ventas, mesas, comandas, atención, cocina, inventarios, costos, caja, reservas, personal y reportes.

### Bares

Necesitan gestionar atención, barra, pedidos, productos, inventarios, caja, eventos, personal y rentabilidad.

### Cafeterías

Necesitan rapidez de atención, ventas, productos, recetas, modificadores, insumos, inventarios y control de caja.

### Hoteles y hospedajes

Pueden necesitar gestión de huéspedes, habitaciones, reservas, servicios, consumos, facturación y operaciones de establecimientos internos.

**Importante:** el módulo hotelero debe tratarse como una línea de producto cuyo alcance real necesita verificarse. No afirmes que existe un PMS completo sin evidencia.

### Eventos y entretenimiento

Necesitan crear eventos, vender entradas, gestionar compradores, generar códigos QR, administrar vendedores y validar accesos.

## 1.3. Audiencias comerciales

El sitio debe dirigirse principalmente a:

- Propietarios.
- Emprendedores.
- Administradores.
- Gerentes generales.
- Gerentes de operaciones.
- Responsables administrativos.
- Empresarios con múltiples establecimientos.
- Organizadores de eventos.

Estos visitantes no necesariamente conocen términos como ERP, API, multi-tenant, SaaS o POS.

Comunica los beneficios de manera comprensible.

# 26. FASES DE EJECUCIÓN

Quiero que trabajes por fases.

Pero cada fase debe producir avances reales.

No te quedes únicamente investigando o planificando.

- Inspeccionar repositorio.
- Revisar agentes.
- Revisar archivos de marca.
- Configurar estructura.
- Registrar decisiones.
- Identificar información pendiente.

**Resultado:** base técnica preparada.

## FASE 1. Investigación y estrategia

- Benchmarking prioritario.
- Arquitectura comercial.
- Posicionamiento.
- Propuesta de valor.
- Audiencias.
- Navegación.
- Estrategia visual.

- Tipografías.
- Tokens.
- Componentes.
- Botones.
- Tarjetas.
- Formularios.
- Navegación.

# 29. CRITERIOS DE ACEPTACIÓN

El proyecto no debe considerarse terminado solo porque la home se vea bonita.

Debe contar con:

- Identidad oficial.
- Diseño profesional.
- Navegación consistente.
- Páginas internas.
- Copywriting original.
- Responsive real.
- Componentes reutilizables.
- Optimización SEO.
- Accesibilidad.
- Mockups conceptuales coherentes.
- Formularios funcionales o dependencias explícitamente pendientes.
- Sin contenido ficticio presentado como real.
- Sin precios inventados.
- Sin testimonios falsos.
- Sin enlaces rotos.
- Sin botones decorativos sin función.
- Build reproducible.
- Documentación.
- Preparación Cloudflare.
- Proyecto GitHub mantenible.

La ausencia de funcionalidades reales verificadas no debe resolverse inventando contenido.

Debe resolverse con comunicación honesta, páginas en borrador y una arquitectura preparada para incorporar los módulos cuando estén disponibles.
